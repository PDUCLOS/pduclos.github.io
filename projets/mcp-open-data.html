IA agentique · Model Context Protocol

Brancher un LLM sur l'open data public

Deux serveurs Model Context Protocol qui permettent à un assistant IA (Claude Desktop, par exemple) d'interroger data.gouv.fr et data.grandlyon.com, y compris les couches géographiques WFS.

Le problème, la réponse, la preuve

Les LLM sont puissants mais ne connaissent pas les données publiques à jour. Le Model Context Protocol standardise la façon de leur donner des outils.

Ces serveurs transforment les API de data.gouv.fr et du Grand Lyon en outils utilisables en langage naturel : « trouve les jeux de données sur la qualité de l'air à Lyon et montre-moi les 10 premières stations ».

Pour le recruteur · valeur business
  • Veille active sur l'IA agentique : MCP est le standard émergent pour connecter les assistants aux données d'entreprise.
  • Même principe transposable à un ERP ou un entrepôt interne.
Pour l'équipe technique · ce que le code prouve
  • SDK mcp bas niveau : handlers list_tools / call_tool, transport stdio.
  • data.gouv.fr : 6 outils (recherche et détail de jeux de données, ressources, organisations, nouveautés).
  • Grand Lyon : 5 outils dont WFS 2.0 GetFeature avec filtre CQL, liste des couches, schéma d'une couche.
  • Client httpx avec timeout, erreurs HTTP renvoyées proprement au LLM ; un Dockerfile par serveur.

Le code qui fait la différence

mcp-data-lyon/server.py — requête WFS avec filtre CQL optionnel

params = {
    "SERVICE": "WFS",
    "VERSION": "2.0.0",
    "REQUEST": "GetFeature",
    "TYPENAME": arguments["type_name"],
    "OUTPUTFORMAT": arguments.get("output_format", "application/json"),
    "COUNT": arguments.get("max_features", 10),
}
if arguments.get("cql_filter"):
    params["CQL_FILTER"] = arguments["cql_filter"]

Limites connues et prochaines étapes
