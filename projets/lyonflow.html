LyonFlow — la mobilité lyonnaise prédite en temps réel

Plateforme MLOps de bout en bout, en production sur VPS : 9 sources open data, architecture Medallion sur PostgreSQL/PostGIS, 27 DAGs Airflow, modèles XGBoost réentraînés automatiquement, routage multimodal pgRouting et un dashboard à 3 personas.

// En 30 secondes

Le problème, la réponse, la preuve

La Métropole de Lyon publie des dizaines de flux ouverts (boucles de comptage, positions des bus TCL, stations Vélo'v, météo, chantiers), mais aucun outil ne les croise pour aider un usager à choisir son mode de transport, un opérateur à piloter son réseau ou un élu à arbitrer un investissement.

LyonFlow collecte ces flux toutes les 5 minutes, les raffine en couches Bronze → Silver → Gold, prédit trafic et disponibilité Vélo'v à H+1h, recommande le meilleur itinéraire multimodal et restitue le tout dans une application pensée pour trois publics.

Pour le recruteur · valeur business
  • Un produit en production, pas un notebook : accessible en ligne, supervisé, sauvegardé chaque nuit.
  • Pensé pour 3 utilisateurs métier (usager, opérateur TCL, élu) — même logique que le pilotage commercial : chaque décideur a sa vue.
  • Le croisement retard bus × congestion distingue un problème opérationnel d'un besoin d'infrastructure (voie dédiée) : un argument chiffré pour un arbitrage budgétaire.
  • Projet porté seul de bout en bout : cadrage, données, modèles, déploiement, documentation RGPD.
Pour l'équipe technique · ce que le code prouve
  • Medallion Bronze/Silver/Gold sur PostgreSQL 16 + PostGIS + pgRouting, SQL paramétré partout, zéro credential en dur.
  • 27 DAGs Airflow (collecte 5 min → 6 h, transforms, ML, maintenance), archivage MinIO S3.
  • MLflow registry (6 modèles, stage Production), retrain XGBoost toutes les 30 min, drift PSI maison + rapports Evidently.
  • CI GitHub Actions : ruff, mypy, bandit, pytest + couverture. Déploiement make deploy-vps / rollback-vps, 20 health checks.
  • Observabilité Prometheus + Grafana + Alertmanager, Nginx seul point exposé, TLS Let's Encrypt.

Architecture de bout en bout

Schéma draw.io généré à partir de l'analyse du dépôt : chaque brique correspond à du code réel. Le fichier source est téléchargeable et modifiable.

⤢ Plein écran (SVG)⬇ Fichier .drawio✎ Ouvrir dans draw.io
  1. Collecte — 9 sources ouvertes sans clé, DAGs Airflow cadencés de 5 min (trafic, bus, Vélo'v) à 6 h (vigilance météo).
  2. Bronze — stockage brut JSONB immuable : on peut toujours rejouer l'historique.
  3. Silver — déduplication (DISTINCT ON), parsing SIRI, reprojection géographique (4326 / 2154), filtrage des capteurs défaillants.
  4. Gold — features ML (lags, moyennes glissantes, calendrier scolaire, météo) et vues matérialisées métier (goulots, retards par tronçon).
  5. Modélisation — XGBoost vitesse H+1h (inférence toutes les 15 min), XGBoost Vélo'v H+1h, routage voiture pgr_dijkstra sur le réseau OSM avec vitesses injectées.
  6. MLOps — suivi MLflow, comparaison continue aux données TomTom, rapport de dérive quotidien, réentraînement automatique.
  7. Restitution — API FastAPI (prédiction, recommandation, goulots) et dashboard Streamlit 18 pages / 59 widgets, sans aucune donnée simulée.

Le code qui fait la différence

src/monitoring/psi.py — dérive PSI robuste, sans dépendance lourde

def _safe_psi_term(pct_ref: float, pct_curr: float, eps: float = 1e-6) -> float:
    """Un terme de la somme PSI, protégé contre log(0) et division par 0."""
    if pct_ref < eps and pct_curr < eps:
        return 0.0
    if pct_curr < eps:
        pct_curr = eps
    if pct_ref < eps:
        pct_ref = eps
    return (pct_curr - pct_ref) * np.log(pct_curr / pct_ref)

Limites connues et prochaines étapes

Documenter honnêtement les limites fait partie du travail : c'est ce qui permet à une équipe de décider en connaissance de cause.

  • Serveur unique : pas de haute disponibilité. La cible Kubernetes (EKS/GKE) existe sur une branche dormante.
  • Prédiction des retards bus encore en phase d'analyse : la donnée SIRI doit s'accumuler avant de passer en production.
  • Sauvegarde hors site : configuration rclone à finaliser.
  • Variante Databricks en cours : semaine 1 livrée (Unity Catalog, ingestion Bronze, DLT), MLflow / Model Serving / Genie à venir.
