Power BI : cette hausse fournisseur est-elle justifiée ?

Projet Power BI de bout en bout pour les acheteurs industriels : il confronte chaque tarif aux cours réels des matières (indices INSEE), chiffre ce qui est renégociable, alerte avant le fournisseur, vérifie que chaque site du groupe paie le meilleur prix et mesure ce que la négociation a rapporté. Modèle généré par script en PBIP / TMDL, 103 mesures DAX, sécurité par ligne, machine learning testé contre une référence naïve.

// En 30 secondes

Le problème, la réponse, la preuve

Chaque année, les fournisseurs annoncent une hausse « à cause des matières premières ». L'acheteur négocie souvent à l'aveugle : aucun lien chiffré entre la hausse demandée et l'évolution réelle des matières qui composent le produit, des baisses rarement répercutées (effet cliquet), un fournisseur qui connaît les cours avant lui, et, dans un groupe qui a racheté des sites, le même article payé plus cher d'un site à l'autre.

Buyvera BI suit les questions que l'acheteur se pose avant un rendez-vous, dans l'ordre : détecter, chiffrer, cibler, comprendre, négocier, puis aligner les prix du groupe et prouver les gains. Démonstration : indices matières INSEE réels ; tarifs, volumes, sites et fournisseurs fictifs, générés avec une graine fixe.

Pour le recruteur · valeur business
  • Une question métier avant les données : la logique vient de 20 ans de terrain B2B industriel.
  • Un parcours, pas un tableau de chiffres : 5 étapes qui suivent la préparation d'un rendez-vous fournisseur, jusqu'à la contre-proposition.
  • Démonstration complète : de la lettre de hausse du fournisseur à la contre-proposition, puis aux gains, sur un jeu de données fictif.
  • Honnêteté sur le ML : le projet montre où le machine learning n'apporte rien, et le prouve par un backtest.
Pour l'équipe technique · ce que le code prouve
  • Modèle en étoile PBIP / TMDL entièrement généré par script et versionné dans Git : 26 tables, 26 relations un-vers-plusieurs à filtrage unidirectionnel, 13 pages.
  • Table pont article × matière sans relation bidirectionnelle : hausse justifiée calculée article par article puis pondérée par les volumes.
  • Précalcul Python des hausses par article × campagne × fenêtre × décalage : les mesures répondent en une seconde, au centime près.
  • Sécurité par ligne (rôles Acheteur et Direction, USERPRINCIPALNAME()), testée ; chaque table, colonne et mesure documentée.
  • Contrôles bloquants, tests DAX sur le moteur local de Power BI Desktop, contrôle croisé Power BI / Python à l'écart nul sur 5 chiffres clés.
// Présentation

Le projet en 2 minutes

2 min, sans voix off · générée par script (Pillow, FFmpeg) à partir des vraies captures du rapport, sur un seul fournisseur fictif suivi du début à la fin : la lettre de hausse, les références, le 80/20, les alertes, la fiche négociation, les prix payés dans le groupe, les gains et le budget 2027.
Montants fictifs du jeu de démonstration, pas des résultats.

Version réseaux sociaux · 24 s, verticale, lisible sans le son : un message toutes les deux secondes.

// Les écrans

Un parcours de négociation, pas un tableau de chiffres

Parcours : 5 étapes (détecter, chiffrer, cibler, comprendre, négocier), chacune avec son chiffre clé et un bouton vers sa page.

Synthèse : combien d'euros renégocier, chez qui, sur quelles familles.

Fournisseurs : hausse demandée face à la hausse justifiée par les matières, animée de 2024 à 2026.

Alertes matières : signal à 3 mois, plafond justifié pour la campagne suivante, plan d'action.

Fiche négociation : argument rédigé, décalage prix / coût matière et simulateur de contre-proposition.

Prix payés : surcoût de chaque site face au meilleur prix du groupe, tarifs mal appliqués dans les ERP.

Gains : économies obtenues face au potentiel chiffré avant chaque campagne.

Prévisions : plafond 2027 avec sa fourchette, volumes, segments fournisseurs, lignes anormales.

Captures et vidéos : montants fictifs du jeu de démonstration, pas des résultats.

Chaque modèle passe un backtest chronologique (réentraîné à chaque date sur le seul passé) contre une référence naïve, et n'est gardé que s'il la bat. Sur les cours de métaux, aucun modèle ne fait mieux que le naïf : l'outil le dit, et donne une fourchette plutôt qu'une fausse précision.

Étape par étape

  1. Indices réels — 7 séries INSEE mensuelles (cuivre, aluminium, nickel, zinc, métaux ferreux, naphta) récupérées par l'API SDMX.
  2. Données de démonstration — 3 000 articles, 10 142 lignes de tarifs, 62 095 lignes d'achats ; hausse demandée = hausse justifiée + biais du profil fournisseur + bruit.
  3. Précalcul — hausses par article, vision groupe sur 3 sites, résultats de négociation ; puis machine learning (prévisions, segments, anomalies).
  4. Contrôles — comportements injectés retrouvés automatiquement, tests DAX, recalcul Python des chiffres clés.
  5. Power BI — modèle et rapport générés par script au format PBIP, ouverts dans Power BI Desktop sans licence Pro.
// Points forts

Les points forts de la solution

  1. 01

    Le fait contre l'argument : chaque hausse comparée aux cours réels des matières qui composent l'article.

  2. 02

    BI industrialisée : modèle PBIP / TMDL généré par script, versionné, documenté, sécurité par ligne testée.

  3. 03

    Chiffres vérifiés : définitions uniques en Python et en DAX, contrôle croisé à l'écart nul.

  4. 04

    ML sans esbroufe : chaque modèle passe un backtest contre une référence naïve, et le naïf gagne quand il le mérite.

// Regard critique

Limites connues et prochaines étapes

Documenter honnêtement les limites fait partie du travail : c'est ce qui permet à une équipe de décider en connaissance de cause.

  • Tarifs, volumes, sites et fournisseurs fictifs : les montants illustrent le fonctionnement, pas un résultat client.
  • Pas d'orchestrateur ni d'intégration continue : le pipeline est une suite de scripts lancés dans l'ordre.
  • Fonctionne dans Power BI Desktop ; la publication sur le service Power BI (rafraîchissement planifié) reste à faire.
  • Hypothèse affichée pour la part non matière (main-d'œuvre, énergie) : +2 % par an.
