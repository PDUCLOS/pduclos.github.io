An ERP copilot that cites its sources and refuses to make things up

A copilot for finance teams on Sage / EBP ERPs: it searches internal procedures, queries the ERP read-only and cites every statement. Open-weight LLM on a local GPU via Ollama, native or LangChain chain, two-judge LLMOps benchmark, Docker image and Kubernetes manifests.

// In 30 seconds

The problem, the answer, the proof

A CFO asks: “A customer is 70 days late, do they keep their discount?” or “Which invoices are more than 60 days overdue?”. Half of the answer lives in procedures and contracts, the other half in the management data. A generic chatbot answers confidently and without sources, inventing an amount if needed.

This copilot combines hybrid document search with a guarded SQL tool. It cites every sentence [S1] and refuses when nothing covers the question. The LLM runs on the company's own GPU, and every version is measured before release.

For recruiters · business value
  • A complete LLMOps loop, documented end to end: measure, detect a hallucination, find its cause, fix it, verify.
  • Rigour on numbers: amounts and days overdue come from SQL, never from the model — the condition for a finance team's trust.
  • Confidentiality: no customer data leaves the machine. The same code switches to Azure OpenAI through one variable.
  • Delivered as a product: chat interface, showcase page, video, Docker image and a step-by-step Kubernetes deployment.
For tech teams · what the code proves
  • Hybrid search BM25 + bge-m3 embeddings merged with RRF: hit@5 100%, MRR 0.92.
  • Read-only, double-locked text-to-SQL: validate_readonly_sql() (one statement, allow-listed tables) and a SELECT-only account.
  • Two generation chains with identical citations: native and LangChain LCEL + ChatOllama, with automatic fallback.
  • Providers switched by environment variable: extractive (CI), Ollama (gemma4:e4b, qwen3.5:9b) or Azure OpenAI.
  • Real token counts logged on every call (Ollama counters), with cost, latency and role. LLMOps benchmark with two LLM judges from different model families.
  • Industrialisation: CI fixed on a real SQL Server 2022, non-root Docker image, kustomize (local GPU / AKS), ingestion Job, benchmark CronJob.

// LLMOps

Measure, detect, fix, verify

1 · Measure, then detect
  • First benchmark: qwen3.5 at 4.8 / 5 faithfulness, gemma4 at 4.85.
  • The judge spots 3 invented invoice numbers on “invoices over 60 days late”; the “valid citations” metric had missed it.
2 · Fix the root cause
  • The cause was the SQL tool, not the model: it returned every unpaid invoice without ageing.
  • It now computes days overdue in Python and filters on the requested threshold.
3 · Verify
  • New benchmark: 5 / 5 for every model, both judges agreeing.
  • Next metric: completeness (gemma can omit 1 invoice out of 8 without inventing anything).

Step by step

  1. Chunking — procedures and contracts split into 800-character chunks along section titles, so the answer can cite “Commercial policy § 3”.
  2. Embeddings — bge-m3 (1,024 dimensions, multilingual) served by Ollama on the local GPU.
  3. Hybrid search — BM25 for exact terms (invoice numbers, VAT), vectors for meaning, RRF fusion.
  4. SQL tool — for data questions, a guarded read-only query; ageing of unpaid invoices computed in Python.
  5. Grounded generation — numbered sources and a strict instruction: cite every statement, refuse otherwise.
  6. Logging — role, model, real tokens, cost, latency and sources of each call, exposed on /usage.
  7. LLMOps benchmark — 13 questions (incl. off-topic and injection) × 4 configurations, scored by two judges; replayed nightly as a CronJob.

// Code excerpts

The code that makes the difference

agents/safe_sql.py — first lock: a single, read-only statement

statement = sql.strip().rstrip(";").strip()

if ";" in statement:
    raise SqlGuardError("Une seule instruction SQL est autorisée par requête.")

lowered = statement.lower()

first_token = next((t for t in _TOKEN_RE.findall(lowered) if t not in {"("}), "")
if first_token not in ALLOWED_START:
    raise SqlGuardError(
        f"Requête non autorisée : elle doit commencer par SELECT ou WITH (trouvé '{first_token}')."
    )

tokens = set(_TOKEN_RE.findall(lowered))
forbidden = sorted(tokens & FORBIDDEN_KEYWORDS)
if forbidden:
    raise SqlGuardError(f"Mot-clé interdit : {', '.join(forbidden)}.")

providers/llm.py — LLMOps: real counters returned by Ollama

def ollama_usage(data: dict) -> dict[str, float]:
    """Extrait les compteurs d'une réponse Ollama (durées en ns -> ms)."""
    eval_count = int(data.get("eval_count") or 0)
    eval_ms = (data.get("eval_duration") or 0) / 1e6
    return {
        "tokens_in": int(data.get("prompt_eval_count") or 0),
        "tokens_out": eval_count,
        "load_ms": round((data.get("load_duration") or 0) / 1e6, 1),
        "prompt_ms": round((data.get("prompt_eval_duration") or 0) / 1e6, 1),
        "eval_ms": round(eval_ms, 1),
        "tokens_per_s": round(eval_count / (eval_ms / 1000), 1) if eval_ms else 0.0,
    }

// Critical review

Known limitations and next steps

Documenting limitations honestly is part of the job: it lets a team make informed decisions.

  • 13-question benchmark: a regression tool, not a statistical study.
  • Faithfulness does not measure omissions: a completeness metric is the next step.
  • Kubernetes manifests validated by rendering (kubectl kustomize) and the image tested in a container, but not yet applied to a real cluster.
  • Authentication: oauth2-proxy (Entra ID) in front of the cloud Ingress; the business role still has to be derived from Entra ID groups.
