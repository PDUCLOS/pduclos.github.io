The problem, the answer, the proof

Every analyst who works with SAP knows the problem: a CSV export with a shifted column, amounts “1.234,56” and “1,234.56” mixed together, dates like 00.00.0000 or #REF! errors. Manual cleanup takes hours and remains error-prone.

Csvtraitement automates detection, suggests corrections, and lets the user validate before exporting.

For recruiters · business value
  • Born from a day-to-day pain point with SAP extracts.
  • Direct time savings for Procurement, sales administration and management control / finance teams.
  • Human in the loop: no correction is applied without validation.
For tech teams · what the code proves
  • Streaming reads in 10,000-row chunks; Parquet read with iter_batches: no memory saturation.
  • Automatic encoding and separator detection (score mean / (1 + standard deviation)), column typing on a sample.
  • Exact and fuzzy duplicates (SequenceMatcher > 85% with prefix blocking), file reconciliation, personal data masking (email, phone, IBAN, French social security number).
  • 8-tab Tkinter interface, batch CLI, undo / redo, 27 modules with logging, type hints and docstrings.

Step by step

  1. Reads any tabular format, converted into a CSV stream processed in chunks.
  2. Detects the encoding, separator and type of each column on a representative sample.
  3. Cell-by-cell detection of column shifts, weighted quality score, duplicate search.
  4. Suggested corrections (dates, decimals, accounting parentheses, realignment) and optional masking of personal data.
  5. User validation, then XLSX export with corrected cells highlighted and a report sheet.

    counts = [line.count(sep) for line in lines]

    # Skip if never present
