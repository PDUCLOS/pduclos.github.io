Clean ERP exports, even at one million rows

Python application (Tkinter GUI + CLI) that detects and fixes defects in ERP exports: shifted columns, FR/US decimals, invalid dates, masked values, duplicates, personal data — with human review before export. Tested on 1,000,000 rows against ground truth.

// In 30 seconds

The problem, the answer, the proof

Every analyst who works with SAP knows the problem: a CSV export with a shifted column, amounts “1.234,56” and “1,234.56” mixed together, dates like 00.00.0000 or #REF! errors. Manual cleanup takes hours and remains error-prone.

Csvtraitement automates detection, suggests corrections, and lets the user validate before exporting. To find out what it is really worth, it was measured on synthetic exports where every injected defect is known: the measurement revealed six bugs in the code, fixed since.

For recruiters · business value
  • Born from a day-to-day pain point with SAP extracts.
  • Direct time savings for Procurement, sales administration and management control / finance teams.
  • Human in the loop in the GUI: no correction applied without validation, undo / redo.
  • Verification mindset: each claim of the project page re-checked, measured, and corrected when it was wrong.
For tech teams · what the code proves
  • Streaming reads in 10,000-row chunks (csv.reader); Parquet read with iter_batches.
  • Automatic encoding and separator detection (score mean / (1 + standard deviation)), column typing on a sample.
  • Realignment of shifted rows: a text field split by an unescaped separator is stitched back, not truncated.
  • Exact and fuzzy duplicates: multi-key blocking on discriminating columns + difflib prefilter (same decisions as ratio()).
  • Personal data masking (email, phone, IBAN, French social security number), PII columns detected automatically.
  • 8-tab Tkinter interface, batch CLI; CLI Docker image and Kubernetes CronJob (kustomize) for nightly processing.

// Approach

Measure, fix, verify

1 · Measure against ground truth
  • Synthetic ERP export generator: 11 SAP-style columns, 8 known injected anomaly types.
  • Benchmark from 10,000 to 1,000,000 rows: time, memory, detection rate, false positives.
2 · Fix what the measurement reveals
  • Unusable CLI: every analysis raised UnboundLocalError.
  • Quadratic fuzzy duplicates: a single block as soon as the 1st column has a constant prefix; 240 s → 2.0 s on 10,000 rows.
  • Text lost during realignment (“Martinez;SARL” lost “SARL”): 32% → 100% of rows restored.
  • Masked values never cleaned (#REF! exported as is); --compare / --reconcile: 0/2 → 2/2 differences found.
3 · Verify
  • 100% of column shifts found, 0 false positives, identical rates from 10,000 to 1,000,000 rows.
  • 84 pytest tests passing (59 initially, all passing too).
  • README fixed: it advertised an MIT license, while the LICENSE file is “all rights reserved”.

Step by step

  1. Reads any tabular format (6 read: CSV, XLSX, XLS, ODS, JSON, Parquet), converted into a CSV stream processed in chunks.
  2. Detects the encoding, separator and type of each column on a sample (first 1,000 + 1,000 random rows).
  3. Cell-by-cell detection of column shifts, weighted quality score, exact and fuzzy duplicate search.
  4. Suggested corrections (ISO dates, decimals, accounting parentheses, masked values, realignment) and optional masking of personal data.
  5. User validation, then export (5 formats written) — in XLSX, corrected cells highlighted and a report sheet.
  6. On a server: the same CLI, without GUI, scheduled every night by a Kubernetes CronJob.

// Critical review

Known limitations and next steps

Documenting limitations honestly is part of the job: it lets a team make informed decisions.

  • Memory: reading is streamed, but every modified row is kept for review (preview, undo); memory grows linearly (1.47 GB after corrections at 1M rows, 2.4 GB peak with XLSX export). Next step: a “counters only” batch mode.
  • Synthetic data only: not yet tested on real exports (mixed encodings, multiple headers, subtotals).
  • Lenient quality score: 92.7/100 (A) on a file where 6.5% of rows are defective; track the non-compliant row rate instead.
  • Ambiguity: a missing cell next to a masked value cannot be placed with certainty (4 cases out of 1,503 in an exploratory run); the final result is correct, but the position of the gap is arbitrary.
  • Whitespace: the space following a separator is dropped on read (“Martinez; SARL” becomes “Martinez;SARL”).
  • Duplicates: the index keeps all rows in memory; not measured at 1M rows.
  • Formats: 6 read, 5 written (no XLS); XLS reading untested for lack of a file.
  • CLI: with --fix, corrections are applied directly (JSON report), without human review.
  • Deployment not verified: docker build / docker run not executed, no cluster available; the 2 Gi limit is derived from measured peaks. No GitHub Actions CI.
