Agentic AI · Model Context Protocol

Connecting an LLM to public open data

Two Model Context Protocol servers that let an AI assistant (Claude Desktop, for example) query data.gouv.fr and data.grandlyon.com, including WFS geographic layers.

The problem, the answer, the proof

LLMs are powerful but have no knowledge of up-to-date public data. The Model Context Protocol standardizes how tools are provided to them.

These servers turn the data.gouv.fr and Grand Lyon APIs into tools usable in natural language: “find datasets on air quality in Lyon and show me the first 10 stations”.

For recruiters · business value
  • Active monitoring of agentic AI: MCP is the emerging standard for connecting assistants to enterprise data.
  • The same approach can be applied to an ERP or an internal data warehouse.
For tech teams · what the code proves
  • Low-level mcp SDK: list_tools / call_tool handlers, stdio transport.
  • data.gouv.fr: 6 tools (dataset search and details, resources, organizations, latest additions).
  • Grand Lyon: 5 tools including WFS 2.0 GetFeature with CQL filter, layer listing, layer schema.
  • httpx client with timeout, HTTP errors returned cleanly to the LLM; one Dockerfile per server.

Step by step

  1. The assistant discovers the tools exposed by each server (name, description, JSON schema of arguments).
  2. When the question calls for it, it invokes a tool; the server queries the corresponding public API.
  3. The response is formatted as Markdown and returned to the model, which summarizes it for the user.

The code that makes the difference

mcp-data-lyon/server.py — WFS request with optional CQL filter

params = {
    "SERVICE": "WFS",
    "VERSION": "2.0.0",
    "REQUEST": "GetFeature",
    "TYPENAME": arguments["type_name"],
    "OUTPUTFORMAT": arguments.get("output_format", "application/json"),
    "COUNT": arguments.get("max_features", 10),
}
if arguments.get("cql_filter"):
    params["CQL_FILTER"] = arguments["cql_filter"]
