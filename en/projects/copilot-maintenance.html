The problem, the answer, the proof

A maintenance technician wastes time looking up a tolerance, a tightening torque or a part reference in catalogs hundreds of pages long. Online AI assistants raise an industrial confidentiality issue.

This copilot answers in French or English, cites its sources (catalog and page) and runs entirely on an Apple Silicon machine, with no API key.

For recruiters · business value
  • Generative AI applied to a real pain point in the field, drawn from 20 years in industrial distribution.
  • Confidentiality by design: no data leaves the machine, transparency documented in line with the AI Act.
  • Sourced, verifiable answers: business user trust comes before demo appeal.
For tech teams · what the code proves
  • PyMuPDF ingestion → 500-token chunks (50 overlap) → multilingual bge-m3 embeddings (1024 dim) → ChromaDB.
  • Hybrid search: dense + BM25 merged with Reciprocal Rank Fusion, optional cross-encoder reranker.
  • Generation with 4-bit Qwen2.5-7B-Instruct via MLX (Metal), LangChain LCEL chain, FR/EN prompts, controlled 504 timeout.
  • Versioned FastAPI /v1, Prometheus metrics, JSON logs; Ubuntu + macOS CI, ChromaDB integration tests, CodeQL.

Step by step

  1. PDFs are read page by page (page numbers kept for citation) and split into overlapping chunks.
  2. Each chunk is embedded with bge-m3 (multilingual) and stored in ChromaDB; a lexical BM25 index is built in parallel.
  3. For each question, both searches are merged with RRF (robust to different score scales), then reranked.
  4. The local LLM generates an answer grounded in the context, citing the catalog and page.
  5. RAGAS measures faithfulness, answer relevancy, context precision and context recall; each evaluation is frozen as a timestamped snapshot.

src/rag/retriever.py — Reciprocal Rank Fusion of dense + BM25

rrf_contrib = 1.0 / (_RRF_K0 + rank + 1)
if cid in chunk_map:
    chunk_map[cid]["rrf"] += rrf_contrib
    if chunk_map[cid]["chunk"].retrieval_method == "dense":
        chunk_map[cid]["chunk"].retrieval_method = "rrf"
// Critical review

Known limitations and next steps

Documenting limitations honestly is part of the job: it lets a team make informed decisions.

  • Baseline RAGAS scores not yet published: the question / answer set is ready, the measured runs still need to be frozen.
  • Tool-calling agent removed (Qwen / Mistral comparison inconclusive) in favor of a more reliable RAG chain.
  • Deployment limited to Apple Silicon (MLX); a vLLM / llama.cpp variant would allow a Linux server.
