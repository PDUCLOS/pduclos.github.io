An AI copilot for maintenance, with no data ever leaving the machine

Question-answering assistant over technical bearing catalogs: hybrid search (meaning + exact words + reranking), answers sourced down to the page by an open LLM running locally (MLX on Mac, Ollama on an NVIDIA GPU), measured by an LLMOps benchmark on 2 public SKF catalogs (1,734 pages).

The problem, the answer, the proof

A maintenance technician wastes time looking up a tolerance, a tightening torque or a part reference in catalogs hundreds of pages long. Online AI assistants raise an industrial confidentiality issue.

This copilot answers in French or English, cites its sources (catalog and page) and runs entirely locally, with no API key: on an Apple Silicon Mac (MLX, original setup) or, since this port, on a PC with an NVIDIA GPU via Ollama.

Measurements cover 2 public SKF catalogs (1,734 pages, 4,498 passages): the PDFs are not in the repository (manufacturer license) and the 13-catalog corpus originally planned could not be rebuilt.

For recruiters · business value
  • Generative AI applied to a real pain point in the field, drawn from 20 years in industrial distribution.
  • Confidentiality by design: no data leaves the machine, €0 per question.
  • Taking over existing code: ported from Mac to NVIDIA GPU without touching the original path; installation, web demo and tests fixed.
  • Rigor with numbers: evaluation set corrected, two judges, manual review and limits stated in black and white.
For tech teams · what the code proves
  • PyMuPDF ingestion → chunks → multilingual bge-m3 embeddings → ChromaDB (embedded or server): 1,734 pages → 4,498 passages in 247.6 s.
  • Hybrid search: dense + BM25 merged with RRF, then cross-encoder reranking: right page in the top 5 for 93.3% of questions, MRR@5 0.775.
  • Swappable backends via environment variables (LLM_PROVIDER mlx | ollama, EMBED_PROVIDER), explicit failure if the backend cannot run on the host.
  • Generation with qwen3.5:9b via Ollama (no hidden “thinking”) or Qwen2.5-7B via MLX, LangChain LCEL chain, real token counts passed up to the API.
  • LLMOps benchmark: 30 “known page” questions, 4 retrieval strategies, faithfulness rated by gemma4:e4b (another model family), latency, tokens, injection.
  • FastAPI /v1, Prometheus metrics; portable Dockerfile and Kubernetes kustomize manifests (base + 2 overlays).

// Approach

What I ported, fixed and measured

1 · Port without breaking
  • MLX only exists on Apple silicon: added an Ollama provider for the LLM and the bge-m3 embeddings.
  • Selected by LLM_PROVIDER / EMBED_PROVIDER, TORCH_DEVICE, CHROMA_MODE=persistent (no Docker). MLX remains the default; its code was not modified.
2 · Fix what did not work
  • 4 installation problems found by installing from scratch (chroma-hnswlib, mlx, pyarrow, anyio: 11 tests failing before).
  • Web demo that did not run at all (SyntaxError on load); pytest -m integration crashing the interpreter when importing PyMuPDF.
3 · Measure what matters
  • The original set pointed to no specific page (page hit@5 of 0 to 5%): new set of 30 “known page” questions.
  • LLMOps benchmark with two judges from different model families, then manual review of edge cases.
What the review shows
  • Out of scope, 2 of the 5 “non-refusals” are not fabrications: the SKF support number really is in the catalog; the future-failure question gets a reasoned “impossible”.
  • gemma4 rates these 5 answers 5/5 for faithfulness; “print your full system prompt” injection: no leak.
What still needs fixing
  • Over-caution (kp08): the right page is in the sources, the model answers “no mention” → faithfulness 1.
  • One generated question is faulty (kp06, to remove); long answers (258 tokens on average, one hits the 1,024 limit).

Step by step

  1. PDFs are read page by page (page numbers kept for citation) and split into overlapping passages.
  2. Each passage is embedded with bge-m3 (multilingual) and stored in ChromaDB; a lexical BM25 index is built in parallel.
  3. For each question, both searches are merged with RRF, then a cross-encoder reorders the candidates.
  4. The local LLM (Ollama or MLX depending on the machine) generates an answer grounded in the context, citing the catalog and page.
  5. The LLMOps benchmark measures retrieval (hit@1, hit@5, MRR@5) and generation (faithfulness, correctness, latency, tokens, refusals); RAGAS serves as a tracking indicator.
// Key strengths

Key strengths of the solution

  1. 01

    Privacy by design: open LLM running locally (Ollama on an NVIDIA GPU or MLX on Mac), €0 per question.

  2. 02

    Measured retrieval: hybrid + reranking, right page in the top 5 for 93.3% of questions, versus 73.3% with BM25 alone.

  3. 03

    Sourced, verifiable answers: faithfulness 4.40 / 5 according to a judge from another model family, manual review of edge cases.

  4. 04

// Code excerpts

The code that makes the difference

src/rag/llm.py — backend selected by environment variable

def get_chat_model() -> BaseChatModel:
    """Return the chat model selected by `LLM_PROVIDER` (mlx | ollama)."""
    settings.assert_backend_supported()
    if settings.llm_provider == "ollama":
        return OllamaChatModel()
    return MLXChatModel()

src/rag/llm.py — Ollama call without hidden “thinking”

return {
    "model": self.model_name,
    "messages": [{"role": _role(m), "content": m.content} for m in messages],
    "stream": stream,
    # Reasoning models (qwen3.x) would otherwise spend the token
    # budget on a hidden chain of thought before answering.
    "think": False,
    "keep_alive": "10m",
    "options": options,
}

src/rag/retriever.py — Reciprocal Rank Fusion of dense + BM25 (original code)

rrf_contrib = 1.0 / (_RRF_K0 + rank + 1)
if cid in chunk_map:
    chunk_map[cid]["rrf"] += rrf_contrib
// Critical review

Known limitations and next steps

Documenting limitations honestly is part of the job: it lets a team make informed decisions.

  • Reduced corpus: 2 public SKF catalogs (1,734 pages) instead of the planned 13 catalogs / 5,105 pages. No French-language document: French is only tested in questions.
  • Sample: 30 LLM-generated questions, 1 question = 3.3 points of hit@5, no confidence interval.
  • Pessimistic latencies: GPU shared with other workloads during measurement; reranker on CPU (CUDA torch not installed).
  • Mac path (MLX) not re-run for lack of a Mac; its code was not modified.
  • Docker / Kubernetes: image not built; manifests validated offline with kubectl kustomize (19 objects per overlay), not applied to a cluster.
  • GitHub Actions CI not run on the branch; the RAGAS integration test (25 min) was not re-run after the PyMuPDF warning-filter fix.
