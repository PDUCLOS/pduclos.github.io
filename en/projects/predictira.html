// In 30 seconds

The problem, the answer, the proof

Respiratory epidemics overwhelm emergency departments every winter, and consolidated hospital data arrives late. The goal: estimate the load of the current week from signals available right away (symptom searches, pollution, weather, flu index).

Training team project (M2i) in a group of 4, revived in 2026: audit, measurement on 2024 against a naive baseline, fixes, a new API and Kubernetes deployment.

For recruiters · business value
  • Honest about the result: against “same value as last week”, the model alone does slightly worse on 2024 (MAE 41.2 vs 39.5). That is stated, along with the lead it opens.
  • Taking over an existing project: six defects reproduced before being fixed, each covered by a test or a validation.
  • Teamwork in a group of 4 on a public-interest topic.
For tech teams · what the code proves
  • LightGBM (100 trees) on 24 features: 12 Google Trends symptoms, CO, NO₂, O₃, PM2.5, SO₂, AQI, pressure, max temperature, flu index, department, year, week (week_cos).
  • Pickle audit (pickletools), allow-list unpickler, export to LightGBM text + JSON: no pickle is loaded at runtime anymore.
  • FastAPI API: Pydantic schema (24 required fields, physical bounds, unknown fields rejected), batches of 1 to 1,000 rows; original Flask interface mounted on / (a2wsgi).
  • Reproducible evaluation (scripts/evaluate.py); inference latency 0.431 ms p50 per row, POST /api/predict 7.05 ms p50 end to end.
  • python:3.12-slim non-root Dockerfile, kustomize base + local / cloud overlays (HPA 2 → 6, NetworkPolicy, PDB).

// 2026 audit

Six defects reproduced, then fixed

Finding (reproduced)Fix
Prefill by exact equality on week_cos: 9 weeks out of 39 returned nothing (floating-point rounding), W27 → W25 and W29 → W23 (same cosine for w and 52 − w). Week rebuilt from row order, then checked against the cosine; a test replays the old filter.
Hidden week_cos field filled with the raw week number (e.g. 10). Cosine computed in the browser; 404 error shown.
Puy-de-Dôme (63) offered in the interface, absent from the data. Department list generated from the data.
Empty field → NaN: a prediction was returned anyway. Pydantic: 400 (empty field), 422 (non-numeric, out of bounds, unknown).
“industrialisation” repository: the client sends 5 features unknown to the model and omits 5; LightGBM predicts by position (1,115 visits, a meaningless value). Client fixed; the API returns 422 listing missing / unknown features.
Models shipped as pickles (code execution possible on load). LightGBM text + JSON export, pickles read through an allow-list; no pickle is loaded at runtime anymore.

Step by step

  1. Weekly table — department × week, week encoded as week_cos (rebuilt from row order, then checked).
  2. Normalization — shipped StandardScaler, read through an allow-list and exported to JSON.
  3. Model — 24-feature LightGBM exported as text: estimate of the week's visits (nowcasting).
  4. Measurement — 429 weeks of 2024 compared with W-1 persistence, by period and by department.
  5. Service — a single application: Pydantic-validated FastAPI API on /api, original Flask interface on /.
  6. Deployment — non-root Docker image, kustomize manifests rendered and validated.

predictira/data.py — the fix (comments in French)

def load_dataset(root: str | Path) -> pd.DataFrame:
    df = pd.read_csv(Path(root) / "df_Test_Indust.csv")
    # week_cos seul est ambigu : cos(2π·w/52) = cos(2π·(52-w)/52), donc S30 et S22 sont
    # indiscernables. Le fichier est trié chronologiquement par département (2024-S01→S39,
    # puis la ligne 2023-S52) : on reconstruit la semaine par le rang, puis on vérifie le cosinus.
    df["week"] = df.groupby(["dept", "year"]).cumcount() + 1
    df.loc[df["year"] == 2023, "week"] = 52
    expected = np.cos(2 * np.pi * df["week"] / 52)
    if not np.allclose(expected, df["week_cos"], atol=1e-9):
        raise ValueError("Ordre des semaines incohérent avec week_cos")
    return df

predictira/safe_load.py — legacy pickles read through an allow-list

class _AllowListUnpickler(numpy_pickle.NumpyUnpickler):
    def find_class(self, module, name):
        if (module, name) not in ALLOWED:
            raise pickle.UnpicklingError(f"classe interdite dans le pickle : {module}.{name}")
        return super().find_class(module, name)

// Critical review

Known limitations and next steps

Documenting limitations honestly is part of the job: it lets a team make informed decisions.

  • Nowcasting: the model estimates the current week from that week's own signals; it is not a 7-day-ahead forecast.
  • On its own it does not beat W-1 persistence on 2024 (MAE 41.2 vs 39.5); combining both is the improvement lead, not yet validated.
  • Only 11 departments of Auvergne-Rhône-Alpes; the department is a numeric feature (31.5% of gain): no generalization to other departments.
  • 39 test weeks, 13 of them in winter: the winter error estimate is fragile. Week encoded without a sine: weeks w and 52 − w are indistinguishable to the model.
  • No data source cited and no training data: retraining is impossible; 2024 being absent from training is likely but not provable.
  • docker build not run during the session (image contents tested in a clean environment); Kubernetes validated by rendering only.
