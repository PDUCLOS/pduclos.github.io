LyonFlow — Lyon mobility predicted in real time

End-to-end MLOps platform for Lyon mobility: 9 open data sources, Medallion architecture on PostgreSQL/PostGIS, 27 Airflow DAGs, quantile XGBoost (P10/P50/P90) one hour ahead, MLflow tracking, PSI drift, pgRouting routing and a dashboard for 3 personas. The problem, the answer, the proof

The Lyon Metropolitan Area publishes dozens of open data feeds (traffic counting loops, TCL bus positions, Vélo'v bike stations, weather, roadworks), but no tool cross-references them to help a commuter choose a transport mode, an operator run its network, or an elected official decide on an investment.

LyonFlow collects these feeds every 5 minutes, refines them through Bronze → Silver → Gold layers, predicts traffic and Vélo'v availability one hour ahead, recommends the best multimodal route and delivers it all in an application designed for three audiences.

For recruiters · business value
  • A product in production, not a notebook: deployed on a server, monitored, backed up every night.
  • Designed for 3 business users (commuter, TCL operator, elected official) — same logic as sales management: each decision-maker gets their own view.
  • Cross-referencing bus delays × congestion separates an operational problem from an infrastructure need (dedicated lane): a quantified argument for a budget decision.
  • Project carried out solo end to end: scoping, data, models, deployment, GDPR documentation.
For tech teams · what the code proves
  • Medallion Bronze/Silver/Gold on PostgreSQL 16 + PostGIS + pgRouting, parameterized SQL throughout, zero hard-coded credentials.
  • 27 Airflow DAGs (collection every 5 min → 6 h, transforms, ML, maintenance), MinIO S3 archiving.
  • Quantile XGBoost (P10/P50/P90): speed trained daily, Vélo'v hourly, inference every 15 min; MLflow tracking with fallback to a local model.
  • Custom PSI drift (daily report), Evidently optional; Prometheus + Grafana + Alertmanager, 7 alert groups.
  • GitHub Actions CI: ruff, mypy, bandit, pytest + coverage. Deployment via make deploy-vps / rollback-vps, Nginx as the only exposed entry point.
  • Kubernetes target: kustomize base + dev / prod overlays + monitoring component, rendering validated with no errors.

What I checked and fixed

Checking the figures
  • 27 DAGs confirmed (28 DAG(...) calls, 1 of them legacy).
  • Tests: 650 passing out of 674 collected (not 620), then 653 with 3 added security tests; 0 failures.
  • “Retrain every 30 min” was inaccurate: speed is trained daily at 03:38 (the hourly DAG has been paused since 07/01/2026), Vélo'v hourly at :50; inference every 15 min.
  • 7 Prometheus alert groups confirmed (17 rules).
Fixing
  • Tests not portable to Windows: files read without an encoding (UnicodeDecodeError), fixed with encoding="utf-8".
  • “Service status” page: with the database unreachable it showed a full Python traceback. The Alerts indicator and latest incidents now follow the same rule as the other 3 indicators.

  • Kubernetes: the kustomize base on the dormant branch no longer built. Realigned with main in deploy/k8s; Prometheus / Alertmanager / Airflow UIs protected.

Step by step

  1. Collection — 9 open sources, Airflow DAGs scheduled from every 5 min (traffic, buses, Vélo'v) to every 6 h (weather alerts).
  2. Bronze — immutable raw JSONB storage: history can always be replayed.
  3. Silver — deduplication (DISTINCT ON), SIRI parsing, geographic reprojection (4326 / 2154), filtering of faulty sensors.
  4. Gold — ML features (lags, rolling averages, school calendar, weather) and business materialized views (bottlenecks, delays by road segment).
  5. Modeling — quantile XGBoost speed H+1h (daily training at 03:38, inference every 15 min), XGBoost Vélo'v H+1h (hourly retraining), car routing with pgr_dijkstra.
  6. MLOps — MLflow tracking, comparison with TomTom data, daily PSI drift report (05:30) shown to the personas. Retraining is scheduled, not triggered by drift.
  7. Delivery — FastAPI API (prediction, itinerary, bottlenecks, GDPR) and an 18-page Streamlit dashboard for 3 personas.

src/monitoring/psi.py — robust PSI drift, no heavy dependency

def _safe_psi_term(pct_ref: float, pct_curr: float, eps: float = 1e-6) -> float:
    """Un terme de la somme PSI, protégé contre log(0) et division par 0."""
    if pct_ref < eps and pct_curr < eps:
        return 0.0
    if pct_curr < eps:
        pct_curr = eps
    if pct_ref < eps:
        pct_ref = eps
    return (pct_curr - pct_ref) * np.log(pct_curr / pct_ref)

dashboard/pages/Usager_5_Statut_Service.py — an “Undetermined” indicator rather than a Python traceback

def _kpi_alerts() -> dict | None:
    """KPI #4 — Alertes actives 6h.

    Comme les 3 autres voyants : si la base ne répond pas, le voyant passe
    en « Indéterminé » au lieu d'afficher une trace Python à l'usager.
    """
    try:
        df = cached_recent_alerts(hours=6, limit=50)
    except DashboardDataError:
        logger.warning("Statut service : alertes indisponibles (DB injoignable)")
        return None
    n_total = len(df)
    n_critical = int((df["severity"] == "critical").sum()) if "severity" in df.columns else 0
    return {"n_total": n_total, "n_critical": n_critical}

// Critical review

Known limitations and next steps

Documenting limitations honestly is part of the job: it lets a team make informed decisions.

  • Single server: no high availability. The Kubernetes target is rendered (kustomize) but not yet deployed: image to publish, MinIO, cert-manager, DAGs to validate under KubernetesExecutor.
  • Production operation on the VPS, the MLflow registry and every accuracy metric were not re-checked when this page was updated.
  • POST /api/v1/recommend still returns a hard-coded example; GET /api/v1/models shows frozen metrics when MLflow is unreachable.
  • Unfixed UI defects: a visible </div> tag and truncated text on the home page; inconsistent version numbers (README, /health, OpenAPI).
  • Bus delay prediction is still in the analysis phase: SIRI data needs to accumulate before going to production.
  • Databricks variant in progress: week 1 delivered (Unity Catalog, Bronze ingestion, DLT), MLflow / Model Serving / Genie to come.
