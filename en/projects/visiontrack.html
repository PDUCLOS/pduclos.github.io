Computer vision · People and road traffic · 100% on-premise

Count, track and measure people and vehicles without a single image leaving the site

Real-time computer vision pipeline on a PC with a consumer NVIDIA GPU: RF-DETR detection, ByteTrack tracking, distance from a fusion of geometry and Depth Anything V2 depth, counting lines, restricted zones and heatmap. A road-traffic profile adds each vehicle's speed in km/h, speeding and wrong-way alerts, counts by type and flow. Everything is configured in one YAML file; outputs are an annotated video and JSON Lines.

The problem, the answer, the proof

Counting store entries, detecting a person in a hazardous area or measuring crowd density: market offerings usually send images to the cloud and charge per camera. For many sites, that is a GDPR blocker as much as a cost that grows with volume.

VisionTrack does everything on site, on a single GPU PC: detection, tracking, distance in meters, counting and zone alerts. Only metrics (counts, JSON) leave the site, and only if wanted. Adapting it to a new site happens in config.yaml, without touching the code.

For recruiters · business value
  • Compliance by design: no image leaves the local network, no per-camera subscription.
  • Built as an offering: site audit, 2-week POC on the client's videos, then deployment and training.
  • Concrete use cases: retail (footfall, heatmap), safety (restricted zone), events, smart city, warehouses, sports, and road traffic (speed, speeding, wrong way, flow by vehicle type).
  • Technical honesty: distance is presented as an estimate (±15–20% without calibration), with how to make it reliable.
For tech teams · what the code proves
  • RF-DETR detection (Apache 2.0) or optional YOLO; ByteTrack tracking with stable IDs and trails.
  • Tracker thresholds automatically aligned with the detector confidence, so detections deliberately kept are not rejected.
  • Distance: geometry (focal length × height / box height), Depth Anything V2 depth in fp16 on GPU, or a fusion that rescales relative depth to meters; exponential smoothing per track.
  • Counting lines and restricted zones, heatmap; outputs annotated MP4 + JSON Lines (one line per frame: tracks, distances, zones).
  • Road-traffic profile (config_trafic.yaml): cars, trucks, buses, motorcycles, bicycles; speed in km/h, calibrated (4 ground points and their real dimensions) or automatic; speeding confirmed after 0.7 s; direction of travel per lane (polygon + arrow) and wrong-way alert; counts by type and flow in vehicles/min.
  • Live local Gradio interface (15 test videos, webcam, YouTube URL streamed, real-time mode); demo videos and reel generated by script from the real pipeline.

Step by step

  1. Source — YouTube video (cached), file, webcam or RTSP stream; excerpt and resolution configurable.
  2. Detection — RF-DETR (nano to large) keeps the requested classes (people by default) above the chosen confidence threshold.
  3. Tracking — ByteTrack gives each person a stable ID and keeps lost tracks for a few moments (occlusions).
  4. Distance — fusion of the geometric method and the depth map, computed every other frame to stay real time, then smoothed per track.
  5. Zones and rendering — in / out counting, restricted-zone alerts, heatmap; annotated video, JSON Lines and statistics in the Gradio interface.
  6. Traffic profile — from the tracks, each vehicle's speed in km/h, speeding and wrong-way alerts per lane, counts by type and flow.
// Key strengths

Key strengths of the solution

  1. 01

    100% on-premise: no image leaves the site, no cloud or per-camera subscription, works offline.

  2. 02

    Real time on consumer hardware: 29 frames/s at 1280×720 for the whole pipeline on an RTX 4070 Ti SUPER, 40 in a light configuration.

  3. 03

    People and vehicles: the same tool counts passers-by or measures a road's speed and flow, depending on the profile.

  4. 04

    Reliable distance in crowded scenes: geometry + depth fusion takes over when a person is sitting or occluded.

  5. 05

    Configurable: source, model, classes, zones and thresholds in a single YAML file.

// Code excerpts

The code that makes the difference

visiontrack/pipeline.py — the tracker does not reject what the detector kept

conf = cfg["detector"]["confidence"]
tracker_cfg["track_activation_threshold"] = min(tracker_cfg["track_activation_threshold"], conf)
tracker_cfg["high_conf_det_threshold"] = min(tracker_cfg.get("high_conf_det_threshold", 0.6), conf + 0.15)
tracker = ByteTrackTracker(frame_rate=src_fps, **tracker_cfg)

config.yaml — adapting to a site without touching the code

detector:
  backend: rfdetr       # rfdetr (Apache 2.0) | yolo (Ultralytics, AGPL-3.0)
  model: medium
  confidence: 0.45
distance:
  method: fusion        # pinhole | depth | fusion | none
  horizontal_fov_deg: 65
zones:
  lines:
    - name: passage
      start: [0.05, 0.75]
      end: [0.95, 0.75]
// Critical review

Known limitations and next steps

Documenting limitations honestly is part of the job: it lets a team make informed decisions.

  • No automated tests or continuous integration yet: the demo came first; to add before a client engagement.
  • Distance estimated without calibration (±15–20%): on a real engagement, set the actual field of view or calibrate the camera.
  • Full pipeline (with depth) on an x86 PC with an NVIDIA GPU (CUDA); on CPU only, 26 frames/s but without the depth map.
  • Vehicle speeds are estimated, not certified; on overhead views they are shown without speeding alerts.
  • Wrong-way alert built but not shown in the demo: no real royalty-free footage was available.
  • YOLO backend under AGPL-3.0, and Depth Anything Base / Large or “Metric” models: check the license before commercial use.
