// How I reason

Engineering decisions I can discuss in an interview

Architecture choices
  • 3 specialized models rather than one (LyonFlow): MAE 5.8 → 3.2, because road features are noise for bikes.
  • Custom PSI rather than Evidently everywhere: lightweight, no heavy dependency in Airflow; Evidently kept for reports.
  • Python consumer rather than Flink when PyFlink doesn't compile on ARM64 — documented, with the Flink job as an option.
  • A single hardened server before Kubernetes: complexity must be justified by the need.
ML rigor
  • Temporal split so the model never “sees the future” (Stripe, HVAC).
  • Same features at training and inference, in a fixed order, to avoid training/serving skew.
  • Dropped a more accurate but unservable model (fraud V1 on PCA features).
  • Judge a retrain on served performance, not just offline.
